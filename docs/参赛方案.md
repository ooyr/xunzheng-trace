# 循证 Trace · 参赛方案

> 像 Git 一样调查，让结论有迹可循。

本文件说明产品定位、实现边界和参赛准备。规则查阅日期：2026 年 10 月 24 日；功能是否可用以当前版本和实际测试为准，本文不代表已完成真实 API 联调。

## 作品定位

循证 Trace 是一个可以回看过程、比较假设的 AI 调查工作台。用户提交文字、网页链接或已有截图，先核对 AI 拆出的待查主张，再选择来源范围，逐步收集证据，形成带原始链接的调查报告。

核心价值是把“搜到答案”变成可检查的过程：问题如何拆解、每一步查了什么、哪些来源相互支持、哪里仍有矛盾，都留在同一份调查记录中。

## Git 逻辑如何落到调查中

| Git 概念 | 调查中的含义 | 用户能得到什么 |
| --- | --- | --- |
| 仓库 | 一个调查案件 | 问题、计划、证据和结论集中保存 |
| 提交 | 一次新增线索或证据记录 | 回看证据来自哪里、何时纳入 |
| 分支 | 一种假设或另一条调查路线 | 分别验证不同解释 |
| 合并 | 将证据汇入结论 | 保留结论引用的来源 |
| 历史 | 调查过程的版本记录 | 了解结论为什么发生变化 |
| 冲突 | 来源对同一主张存在分歧 | 展示差异，继续查证 |

以上是产品交互的对应关系，不要求真的运行 Git，也不意味着当前版本已具备完整的 Git 式回滚或自动合并能力。

## 可行性与技术路径

网页作为主入口是可行的。React/Vinext 展示工作台，服务端负责模型与搜索调用，浏览器保存当前原型的调查记录，Markdown 用于导出。模型承担拆题、截图文字识别和归纳，元宝搜索提供实际检索证据，两者职责分开。

建议流程：

1. 接收输入，识别主张中的对象、时间、范围和可核验条件。
2. 输出可编辑的调查步骤，用户选择搜索来源。
3. 按步骤调用元宝搜索，保存返回的标题、原始链接、摘要和检索时间。
4. 将证据关联到主张，区分支持、反驳、存在冲突与证据不足。
5. 汇总报告，保留引用和仍待确认的问题。

项目接口按 `/api/status`、`/api/plan`、`/api/search`、`/api/chat` 和 `/api/wechat` 分工。具体可用能力、字段和认证方式以实际代码及接入文档为准；预留接口不等于已连接外部服务。

模型 API 和搜索密钥只进入服务端配置。获得元宝实际端点、认证要求及返回样例后，先用单个公开问题联调，再录制参赛演示。不要把演示样例、模型自行生成的 URL 或未执行的查询写成真实搜索证据。

## 来源选择的实际边界

“官方媒体 / 小红书 / B 站”等选项表示检索偏好或来源筛选。搜索引擎能否覆盖某条内容取决于索引、登录要求和平台限制，不能承诺直连全量平台数据。

- 对原始发布者、官方文档和一手资料优先展示，但“官方”也需要验证域名、发布时间与原文内容。
- 小红书或视频内容可能只有标题和片段，不能据此声称已经阅读全文或观看完整视频。
- 用户提交链接不代表服务端一定能读取正文。提取失败时请用户补充相关文字或已有截图，并保留原链接。
- 截图识别结果需要允许用户纠正；只有接通支持图片的模型并通过测试后，才能宣称自动识图可用。
- 来源条数、检索覆盖率和模型置信度都不等于事实为真的概率。结论应写清证据范围和不足。

## 比赛前的优先级

### 本轮 MVP

- 网页输入、调查步骤、来源选择、调查分支和证据记录形成一条完整体验。
- 本地保存及 Markdown 导出便于演示和复盘。
- 保留元宝与模型适配层，清晰展示“演示 / 未配置 / 真实调用”状态。
- 接上真实元宝后完成 3 次真实查询，点击检查引用，再准备录屏与提交材料。

不把未经验证的能力写入参赛介绍。尤其需要区分：能保存本地记录与跨设备同步、能上传截图与已经完成识图、能打开聊天面板与已经接入微信。

### 后续微信入口

优先考虑微信公众号或企业微信的官方能力。用同一套案件数据和调查引擎，增加文字游戏式指令：`新建调查` → `选择来源` → `执行第 1 步` → `查看证据` → `建立分支` → `导出报告`。

真正上线还需处理平台账号权限、HTTPS 回调、签名校验、消息格式、用户隔离及长任务返回方式。网页中的机器人演练可先验证玩法；未配置平台回调时不应称为已可在微信使用。

### 后续持续盯梢

在用户明确订阅的公开问题上，定期重跑指定步骤，比较新旧证据，只在出现有效变化时提醒。上线前需有服务端持久化、任务调度、配额预算、退订入口和结果去重；当前网页本地保存不能替代后台定时任务。

## 参赛表达

一句话：**把一个问题拆成可验证的线索，像 Git 一样记录分支与证据，用元宝搜索形成可追溯的调查结论。**

三分钟优先展示一个完整案件，再说明另外两次真实查询。把“从错误假设到证据修正”的过程展示出来，比只展示最终答案更能体现作品差异。
