# 后台盯梢调度

盯梢任务与历史保存在托管 D1 的 `trace_monitor_jobs`、`trace_monitor_runs` 中。账号可创建、暂停、恢复或手动复查自己的任务；创建任务不会自动完成第一次检索，任务在到期队列中等待，也可点击“建立基线”。

## 运行入口与访问

`POST /api/monitor-tick` 使用 `Authorization: Bearer ...`，与服务端 secret `MONITOR_RUNNER_TOKEN` 比较。此入口不接受访客 Cookie 作为后台授权，也不会返回令牌。公开站点仍必须通过这层鉴权。

当前部署将本站由 Sites 提供的服务访问令牌配置为 `MONITOR_RUNNER_TOKEN` secret。云任务每次先通过本站 `get_site` 获取服务访问令牌，仅在内存中使用，向同一个站点同时发送以下两个请求头：

- `OAI-Sites-Authorization: Bearer ...`：供 Sites Dispatch 校验并消费，允许云端服务调用到达本站。
- `Authorization: Bearer ...`：供本站 Worker 与 `MONITOR_RUNNER_TOKEN` 比较，保留公开写入口自己的鉴权。

当前配置下两个头使用同一个本站服务令牌，但它们承担不同的授权边界。不能省略平台服务头，也不能让 Worker 改成只校验平台头。令牌只发送到对应站点，不写入提示词、代码、终端参数、文件或结果。若服务令牌轮换，需要同步更新 runtime secret 并重新部署；未同步时应报告本轮鉴权失败，保留原调度等待修复。

## 每次复查的行为

1. 云任务按小时触发一次，读取已经到期且启用的任务，每批最多处理 3 项。
2. 服务端原子领取 2 分钟租约，执行一次元宝 SearchPro，并保存真实请求编号。
3. 首次成功查询保存基线；后续比较规范化 URL 和标题/摘要指纹。
4. 变化或错误保存站内未读提醒，历史最多保留 100 次。失败至少等待 1 小时，不自动即时重试。
5. 租约回写带栅栏，过期的执行者不能覆盖后来的结果。手动复查也受原子冷却限制。
6. 无到期任务时，入口返回 HTTP 200、`processed: 0` 是正常空轮次，不代表复查失败，不应为此重复调用。`processed` 表示本轮形成记录的任务数，仍需检查各条 `runs[].run.status` 是否为 `error`。
7. 单轮请求失败只通知拥有者并等待下次触发，不在本轮重试，不自动暂停、删除或新建云调度。页面任务开关与云调度状态分别管理；任务已开启不等于云调度当前运行正常。

每账号最多 3 项活动任务，全站最多 50 项；每天最多执行 60 次盯梢查询。查询未返回旧链接只表示本轮未出现，不能推断原文删除或内容失实。摘要变化也不能替代正文变化检测。

## 调度与验证

发布后使用 Sites 原生云调度关联本站，保存到期处理计划。该计划处理数据库中的任务，无需打开网页；任务本身的 1/6/24 小时间隔由数据库决定，小时调度可能带来延迟。

创建前读取本站已关联的 automations，复用已有计划。调度提示只描述本站、凭证获取方式、调用入口和结果核对，不包含密钥。完成后检查计划启用状态，并使用上述双头、无浏览器 Cookie 和 Origin 调用一次入口。若有到期任务，随后以任务所属账号读取结果验证持久化；若无到期任务，正常接受 `processed: 0`，不要补造运行记录。

保存了调度不等于已经发生过自动运行；实际验证记录与计划的首次自然触发应分别说明。站内提醒在返回网页时可见，当前不发送微信或邮件通知。
