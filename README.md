# 循证 Trace · 可追溯的 AI 调查工作台

**像 Git 一样调查，让结论有迹可循。**

输入一个问题、一段文字或一张截图，拆解调查步骤，用元宝搜索收集公开资料，再通过证据树和核验分支整理依据，形成带引用、可复查的暂定结论。

[在线体验](https://trace-detective-workbench.primehawk66.chatgpt.site/) · [开发与接入](docs/开发与接入.md) · [验证记录](docs/接入验证.md) · [演示脚本](docs/演示脚本.md)

## 为什么叫「循证 Trace」

「循证」表示沿着证据推进判断，`Trace` 表示保留调查轨迹。搜到的资料、尝试过的解释和结论变化，都留在同一份可追溯的调查记录中。

本项目为 [WaytoAGI 1024 切磋大会·侦探赛道](https://1024.waytoagi.com/tracks/detective) 制作，围绕“少点幻觉，多点搜索”，探索从 AI 搜索到证据整理的完整体验。

## 能做什么

| 能力 | 使用方式与产出 |
| --- | --- |
| 拆解调查问题 | 生成 2–6 步可编辑计划，先确认要查什么、去哪里查 |
| 检索真实来源 | 通过元宝 SearchPro 搜索，保留标题、摘要与可点击原文 |
| 整理证据树 | 按问题、方向和子问题组织资料，查看各步骤的检索状态 |
| 分支核验 | 从历史线索建立另一条调查方向，比较解释，合并可追溯资料 |
| 形成引用答案 | 登录后基于当前分支资料生成可能答案、依据与未解问题，资料变化后提示重新核验 |
| 截图查证 | 登录后识别截图中的可核查主张，再逐条搜索并给出初步核对 |
| 持续盯梢 | 登录后设置 1、6 或 24 小时复查任务，记录检索结果变化与站内提醒 |
| 保存与导出 | 浏览器本地保存、JSON 备份、Markdown 报告；登录后可显式存取账号档案 |

## 三步体验

1. **提出问题**：输入要核查的公共问题，选择来源范围，检查生成的调查计划。
2. **沿着线索搜索**：点击「拆解并自动调查」，逐步收集资料；在结果树中打开原文，有疑问时建立核验分支。
3. **留下判断依据**：登录后生成可能答案，或人工记录暂定结论，导出含原始链接的报告；证据不足的部分保留未知。

例如：输入“月球背面是不是一直照不到太阳？”，把“背面”和“夜晚”拆开调查，分别核读航天或科学机构的原始资料。此处是体验题目，不是预填的真实查询结果。

在线版无需 ChatGPT 账号即可打开。访客每天可体验 2 次拆解、3 次检索；引用答案、截图查证、账号档案和盯梢等功能使用作品自己的账号密码登录。是否能完成真实调用，取决于服务端模型、搜索配置及可用额度。

## 本地运行

需要 **Node.js 22.13+**。Windows PowerShell 先启用 UTF-8：

```powershell
chcp 65001
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
```

```powershell
git clone https://github.com/ooyr/xunzheng-trace.git
cd xunzheng-trace
npm install

# 首次运行：生成配置，并初始化本地 D1 数据库
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_plain_iceman.sql
npm run dev
```

打开终端显示的地址，默认是 `http://127.0.0.1:5173/`。后续新增迁移时，按顺序应用尚未执行的迁移文件。

真实检索需要配置模型和元宝搜索凭据：将 `.env.example` 复制为 `.dev.vars`，仅在本机填写密钥并重启开发服务。未配置时仍可查看示例、整理手动证据和导出报告；示例与规则计划均有明确标识。

完整环境变量、API 契约、操作细节和微信接入说明见 [开发与接入指南](docs/开发与接入.md)。

## 技术组成

React + TypeScript 构建工作台，Vinext / Vite 适配 Cloudflare Workers，D1 保存账号与任务，Drizzle 管理数据结构。模型负责拆题、识图和归纳，元宝 SearchPro 提供检索来源。

## 能力边界与验证

- 判断基于检索摘要，仍需打开原文核读。来源数量和模型置信度不代表事实为真的概率。
- 网页链接用于保留出处，当前不自动提取正文；小红书、B 站等只覆盖公开且被索引的内容。
- 分支用于记录调查方向；计划和来源关系标签在同一档案内共享，尚非完整隔离的 Git 状态快照。
- 盯梢比较检索链接及标题、摘要的变化；任务创建成功不等于后台调度已经成功运行，也不等同于正文变化检测。当前只提供站内提醒。
- 微信目前实现明文回调验签和菜单，正式微信调查仍需持久会话与异步回复服务。

[接入验证记录](docs/接入验证.md) 保存了 2026 年 10 月 24 日的文字计划、图片输入和单次元宝搜索联调结果；它不等同于三次完整参赛查询的录屏或报告。

开发检查命令为 `npm test`、`npm run typecheck` 和 `npm run build`，具体覆盖范围见开发指南。
